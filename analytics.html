Methodology — what "unique" actually means here
Daily unique visitors are counted with a one-way hash of each visitor's IP address + browser, combined with today's date. Because the date is baked in, that exact hash can never repeat on a different day — it fully resets every 24 hours, the same way privacy-respecting tools like Fathom or Plausible work. Raw IP addresses are never stored anywhere, only this hash.

New vs. repeat visitors need a second hash that does not include the date, so it can actually recognize the same visitor coming back on a later day. Honest tradeoff, not hidden: this second hash is coarser and longer-lived than the daily one — it persists as long as a visitor's IP + browser combination stays the same, realistically days to weeks for most people, and changes the moment they switch networks or devices. It is still fully anonymous and one-way hashed; it is simply not reset every 24 hours the way the daily hash is.

Known limitation: visitors are identified by device/browser, not by person — the same person on their phone and then their laptop the same day will show as two visitors. Every privacy-respecting analytics tool has this exact limitation, Fathom and Plausible included.

Week-to-date / month-to-date / all-time totals above are a sum of daily unique counts, not a fully deduplicated count across that whole range — a person who visits three separate days in one week is counted three times toward that week's total, not once. A true multi-day deduplicated count is a possible future addition, not built yet.

Commissioner Portal and Admin Portal traffic (Greg's and Yeti's own login-gated tools) is tracked separately as plain pageview counts and is never included in any number above — it isn't real audience.
